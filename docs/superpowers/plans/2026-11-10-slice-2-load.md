## Review Focus

1. Criterion 4 says "the same state": `afterSwitch` during rejection returns `this` (spec 5.6), so the test uses `assertSame`, not only `assertEquals`. Covered by `switchDuringRejectionIsIgnored`.
2. Clamp before the rejection check: from `load` 90 the result is exactly 100 and rejection starts. An implementation that checks `load + 25 >= MAX` but stores 115 would fail. Covered by `switchFromNinetyClampsAndRejects`.
3. Decay never goes below 0 even from a value that is not a multiple of 0.25 (`load` 0.1 → 0 after one tick). Covered by `decayFromFractionStopsAtZero`.
4. During rejection `load` stays exactly `MAX` on every tick (the HUD bar stays full), and the last tick sets `rejectionTicks` 0 and `load` 0 together. Covered by `rejectionHoldsMaxThenClears`.
5. `tick` on `EMPTY` stays `EMPTY` (no negative load, no phantom rejection). Covered by `tickOnEmptyStaysEmpty`.

  ```java
  package io.github.evgenius09.threshold.core;
  public record LoadState(double load, int rejectionTicks) {
      public static final double MAX = 100.0;
      public static final double SWITCH_COST = 25.0;
      public static final double DECAY_PER_TICK = 0.25;
      public static final int REJECTION_TICKS = 160;
      public static final LoadState EMPTY = new LoadState(0.0, 0);
      public boolean rejecting();
      public LoadState afterSwitch();
      public LoadState tick();
  }
  ```

- [ ] **Step 3: Implement `core/LoadState.java` and bump the version**

Record with the components, constants and methods from the Interfaces block, values exactly as listed. Set `version=0.1.2` in `gradle.properties`.

- `rejecting()`: `rejectionTicks > 0`.
- `afterSwitch()`: if `rejecting()` return `this`. Otherwise `next = Math.min(MAX, load + SWITCH_COST)`; return `new LoadState(next, next == MAX ? REJECTION_TICKS : 0)`.
- `tick()`: if `rejecting()`: `left = rejectionTicks - 1`; return `new LoadState(left == 0 ? 0.0 : MAX, left)`. Otherwise `new LoadState(Math.max(0.0, load - DECAY_PER_TICK), 0)`.

One comment, on `tick`: why load stays at `MAX` during rejection (the HUD bar stays full until rejection ends, tech.md 5.6). No Javadoc.
